# Dino Chat 行为与 AI 质量看板需求

## Problem Statement Brief

Dino 团队需要判断真实对话是否实现了产品设计意图，而不只是了解消息量或用户画像。当前需要把用户行为、AI 承接质量和可复盘的 bad case 放在同一套证据链中，帮助团队定位产品迭代优先级。

## 设计意图

依据当前 Dino 对话规范：

1. 对话应是轻松、自然的课后聊天，而不是测试、操练或纠错。
2. Dino 应承接孩子最新表达，并提出一个清晰、可回答的新问题。
3. 用户说听不懂、不知道或不会表达时，Dino 应降低难度并提供适当帮助。
4. 对话应允许孩子分享生活、偏好和问题，而不只是被动回答 Dino。
5. Dino 不应重复问题、连续要求重说、提出多个问题、假设能看见孩子或索取隐私信息。

## Need Hierarchy

### Must

- 按入口和时间分析用户在对话中做什么。
- 识别用户问题、生活分享、偏好、非英语使用、理解求助和回答困难。
- 衡量 AI 是否回应用户问题及困难信号。
- 聚合 AI bad case，并展示匿名 transcript 上下文作为证据。
- 明确自动分析口径和不可判断的数据缺口。

### Should

- 对比首页、练口语和 Post-class practice 的行为与质量差异。
- 将结论组织为“设计目标—当前基线—风险—产品建议”。
- 让入口和日期筛选同步作用于用户指标、AI 指标和证据。

### Could

- 后续配置产品目标值并显示达标状态。
- 关联用户年龄、级别、国家、性别和课程上下文。
- 加入人工标注抽检，校准自动分类准确率。

## Constraint Inventory

### 已确认事实

- 数据包含 message_id、user_id、session_id、entry_type、sequence_no、role、content、created_at。
- 当前导出不包含用户年龄、级别、国家、性别、课程内容、对话阶段或语言策略。
- transcript 含儿童口语和语音识别噪声。
- “使用非英语”与“听不懂/求助”为独立、可重叠信号：前者判断语言，后者判断语义意图。

### 分析假设

- 消息顺序可以用来配对 User → Dino 回应。
- 关键词、句式和相邻上下文适合做趋势筛查，但不能替代人工质检。
- 在没有业务目标值时，只报告当前基线和风险方向，不宣称“已达标”。

## Scope Definition

### V1

- 用户行为与困难分析。
- AI 承接与帮助指标。
- 八类可解释 bad case 检测。
- 每类结论的匿名 transcript evidence。
- 入口与日期筛选。

### 暂不纳入

- 基于用户人口属性的交叉分析。
- 课程内容一致性和分级语言合规判断。
- 对单个用户做人格或能力画像。
- 将自动规则结果作为最终质量评分。

## 验收标准

- 看板不再出现用户 Persona 分析。
- 用户层、AI 层和 Bad case 层均有独立结论与证据。
- 用户点击行为或 bad case 类型，可查看对应 User → Dino 原始片段。
- 所有证据不展示真实 user_id 或 session_id，并过滤邮箱、网址和长数字标识。
- 没有可靠上下文支持的判断必须标为“不可判断”或“当前基线”。
